## 1. Executive Summary of the Review

All three architecture drafts converge on the core macro-architecture required by the product context:
1. **One shared trilingual (`ar-DZ` RTL, `fr-DZ` LTR, `en` LTR) Flutter owner application** using local **encrypted SQLite (`drift` + `sqlite3` `sqlite3mc` build hook with explicit `chacha20` ChaCha20-Poly1305 256-bit AEAD)** for offline-first persistence across both **WalimApp Local** (single-device offline edition) and **WalimApp Connect** (multi-user, multi-device synchronized edition), with Connect capabilities unlocked via entitlements rather than maintaining separate codebases.
2. **Client-generated UUIDv7 primary keys**, **integer whole Algerian Dinars (`BIGINT` `DZD`, column suffix `*_dzd`)**, and an **unconditionally append-only financial ledger** from Day 1 so Local-to-Connect migration preserves record identities without foreign-key rewriting or 100x unit conversion errors.
3. **One Laravel modular monolith** backed by **one PostgreSQL 17 (`17.x` GA) database**, serving the Connect REST/Sync API, the **server-rendered (Blade + Tailwind CSS + Alpine.js)** trilingual (`/ar`, `/fr`, `/en`) public marketplace, and the trilingual **Filament** super-admin panel—without microservices, Kubernetes, or mandatory Redis.

However, a rigorous line-by-line inspection and our Phase 0 / 0.2 / 0.3 / 0.3.1 / 0.3.2 reviews ([`docs/walimapp-phase0-audit.md`](./walimapp-phase0-audit.md), [`docs/walimapp-phase0-audit-round2.md`](./walimapp-phase0-audit-round2.md)) uncovered **material contradictions between the drafts**, **one truncated draft**, **an outdated 58-Wilaya assumption**, **unsafe migration and sync patterns in one draft**, **unit mismatches (centimes vs. whole DZD)**, **upstream package deprecation (`sqlcipher_flutter_libs` EOL in favor of `sqlite3: ^3.8.0` `sqlite3mc` build hooks with explicit `chacha20` cipher selection)**, and **product scope expansions (shared Android/Windows Flutter app, interleaved Connect delivery, atomic retry-safe tiered `1` vs. `5` active-device plans, immediate server revocation vs. next-online local crypto-erasure, fail-closed `OfflineAccessLease` across reboots, unambiguous `libsodium` `secretstream` vs. fallback STREAM `.walimbak` backup PoT, and full trilingual `ar-DZ`/`fr-DZ`/`en` support)** that none of the three drafts originally addressed.

This document records those findings, reconciles the contradictions, strips away solo-developer overengineering, and establishes full mechanical traceability (`TR-01`..`TR-15`) to the canonical baseline in [`docs/architecture.md`](./architecture.md) and [`docs/decision-register.md`](./decision-register.md).

## 3. Requirements Coverage, Gaps & Contradictions

### 3.1 Requirements Properly Covered Across Drafts
- **WalimApp Local offline autonomy:** 100% offline single-device operation using local encrypted SQLite (`sqlite3mc` via Drift), no LAN sync, no mandatory cloud telemetry or heartbeat (`REQ-LOC-01`..`23`).
- **Perpetual Local licensing:** Ed25519-signed offline `.walimlic` files where update entitlement compares `APP_BUILD_DATE <= updates_until` rather than the wall clock, and checks entitlement *before* running SQLite schema migrations (`REQ-LOC-22`..`23`).
- **Immutable financial ledger:** Append-only `payments` with explicit `refund` / `adjustment` entries (`parent_payment_id` + mandatory `reason`), eliminating silent edits and sync lost-update bugs (`REQ-LOC-12`..`13`).
- **Server-side multi-tenancy & RBAC:** Explicit tenant scoping derived from authenticated membership (`venue_memberships.is_active`, never request payload), venue-scoped employee permissions, and Filament Super-Admin with append-only `audit_logs` (`REQ-CON-01`..`05`, `REQ-ADM-01`..`07`).
- **Public marketplace & advertising:** Server-rendered Blade + Tailwind CSS + Alpine.js with `/ar` (RTL), `/fr` (LTR), and `/en` (LTR) routes, Schema.org JSON-LD, privacy-safe availability projection, WhatsApp click-to-chat (`wa.me`), staff-curated initial provider directory, and admin ad placements (`REQ-MKT-01`..`11`).
- **360° Virtual Tours deferred to Phase 4:** Equirectangular panoramas with lazy-loaded WebGL viewer (`Pannellum`), explicitly decoupled from Phases 1–3 (`REQ-PH4-01`).

### 3.2 Missing or Contradicted Requirements Identified & Resolved

1. **Contradiction — 69 Wilayas vs. 58 Wilayas & Confirmed Trilingual Scope (`ar-DZ`, `fr-DZ`, `en`):**
   - **Requirement:** Support Algeria's **69-Wilaya structure** (`REQ-LOC-04`, `REQ-MKT-02`) and **three languages (`ar-DZ` RTL, `fr-DZ` LTR, `en` LTR)** across the owner app, public marketplace, and Super-Admin (`NFR-01`).
   - **Draft Contradiction:** `architecture-gemini-argon.md` hard-coded `58 Algerian Wilayas` (`1..58`), and all three drafts covered only Arabic and French.
   - **Correction:** `wilayas` (`code VARCHAR(2)` `'01'`..`'69'`) and `communes` are seeded from a versioned, checksummed dataset verified against official Algerian *Journal Officiel (JORADP)* / ONS listings covering all **69 official Algerian Wilayas** and 1,541 communes in Arabic, French, and English (`ADR-005`, `ADR-014`), with optional per-language venue/provider content (minimum one language required) and deterministic fallback (`en -> fr -> ar`, `fr -> ar -> en`, `ar -> fr -> en`) inside `<bdi>` / `Directionality` containers.
2. **Gap — Shared Flutter Codebase, Value-First Interleaved Sequencing (`DEC-01`) & Atomic Tiered Connect Device Plans (`ADR-013`):**
   - **Requirement:** One shared Flutter codebase targeting both **Android smartphones** and **Windows desktop**, plus tiered Connect plans (**Basic: `1` active device**; **Higher-Capacity: up to `5` active devices** at a higher price, configurable by Super-Admin) with mandatory individual user accounts and RBAC (`NFR-02`, `REQ-CON-01`..`02`, `REQ-ADM-03`).
   - **Draft Gap:** All three drafts targeted Windows desktop only in Phase 1 and did not distinguish active physical device limits (`max_active_devices`) from individual user accounts (`venue_memberships`), serialize concurrent device registrations with retry-safe idempotency, or snapshot `agreed_price_dzd` against silent plan-edit price changes.
   - **Correction:** Elevated Android (`API 24+`) and Windows (`x64`) to co-equal targets in `apps/owner` (`ADR-001`), separated physical venue count (`max_venues = 1`) from unlimited bookable halls (`"max_halls": null` by default, `DEC-02`), adopted **Value-First Interleaved Sequencing (`DEC-01` Option B)**, and modeled `subscription_plans` (`1` vs. `5` active devices), atomic `SELECT ... FOR UPDATE` device-limit locking on `subscriptions` (checking existing `active` registration for the same `device_installation_uuid` first so retries return `200 OK`, backed by `uq_active_device_installation_per_org`), immediate server revocation vs. next-online client cryptographic erasure, a fail-closed 72h `OfflineAccessLease` (requiring online revalidation after any reboot), and `subscriptions.agreed_price_dzd` snapshots (`ADR-013`).
3. **Contradiction — `booking_requests` vs. `reservations` Table Separation:**
   - **Requirement:** Booking requests must be distinct from actual reservations (`REQ-MKT-07`..`10`).
   - **Draft Contradiction:** `architecture-gemini-argon.md` stored public requests inside `reservations` (`status = 'pending_owner_approval'`).
   - **Correction:** Separate `booking_requests` table; owner approval executes an atomic PostgreSQL transaction validating slot availability via `btree_gist`, creating/linking the `customer`, and inserting a `confirmed` `reservation` (`ADR-006`).
4. **Contradiction — Money Units (Centimes vs. Whole DZD):**
   - **Draft Contradiction:** Opus and Sonnet proposed `amount_minor` (centimes), whereas Argon and Algerian wedding hall practice use whole Algerian Dinars (`DZD`). Mixing the two risks 100x calculation bugs.
   - **Correction:** Standardized every table, DTO, checksum, and PDF across all documents on **integer whole Algerian Dinars (`BIGINT` `DZD`, column suffix `*_dzd`)** (`ADR-009`).
5. **Contradiction — Connect Subscription Expiry & Renewal Reconciliation:**
   - **Draft Contradiction:** Opus proposed locking local editing on Connect expiry unless the customer also bought a perpetual Local license; Sonnet and Argon preserved local offline access and editing while pausing cloud sync and public marketplace features.
   - **Correction:** In `expired_local_fallback` (after the grace period in `DEC-09`), cloud sync and public marketplace booking requests pause while local offline access remains 100% functional. Local edits made during expiry queue in `sync_outbox` (`outbox_seq`) and reconcile through the conflict-safe sync pipeline upon subscription renewal (`docs/architecture.md §8.2`).

## 4. Technical Errors & Security Gaps Resolved

### 4.1 Truncated Specification in `architecture-opus.md`
- `architecture-opus.md` terminates mid-sentence at line 1909 (`### 16.5 Backup of media`), omitting `§17`–`§23`. All missing security, backup, testing, ADR, and open-question sections were reconstructed and cross-checked against `architecture-sonnet.md` and `architecture-gemini-argon.md`.

### 4.2 Unsafe In-Place Migration, Missing `local_actors` & Lost-Response Recovery (`P1-5`, `P1-6`, `P1-7`)
- `architecture-gemini-argon.md` (`§13.1`, `§13.3`) mutated local SQLite `organization_id`/`venue_id` before upload and upserted directly into live PostgreSQL tables.
- **Correction (`ADR-011`, `docs/architecture.md §7`):**
  1. Added `local_actors` (`P1-6`) so Phase 1 bookings and payments preserve human operator attribution (`recorded_by_actor_name`, `recorded_by_local_actor_id`) across migration alongside `recorded_by_user_id`.
  2. Staged migration uploads all 12 relational entity types to `migration_staging_records` and uploads all local binaries (`generated_document_pdf` and `venue_logo`) via `migration_assets_manifest` (`P1-7`) directly to content-addressed paths `tenants/{org_id}/venues/{venue_id}/assets/{sha256_checksum}` *before* `Phase M3` commit.
  3. `Phase M3` promotion is a **pure PostgreSQL transaction** (zero S3 move operations inside the DB lock), and persists `migration_sessions.status = 'committed'` + `committed_receipt_json` (`initial_seq`) so a client in `local_migration_state = 'commit_in_progress'` recovers idempotently if the HTTP response is lost (`P1-5`).

### 4.3 Evidence-Based Framework, Database & Crypto Validation
1. **Composer Dependency Solver Evidence (`docs/architecture.md §2.2`):**
   - Executed `composer update --dry-run` (with `platform.php = 8.4.0`) against Packagist metadata on 2026-10-29:
     - **Track 1 (Recommended for Phase 2):** `laravel/framework` `v13.39.0` (security support through `2028-03-17`) + `filament/filament` `v5.11.0` + `livewire/livewire` `v4.4.8` + `laravel/sanctum` `v4.3.3` + `Tailwind CSS v4.1+` resolves cleanly (`110 installs, 0 conflicts`).
     - **Track 2 (Fallback):** `laravel/framework` `v12.70.2` (security support ends `2027-02-24`) + `filament/filament` `v4.16.0` + `livewire/livewire` `v3.8.11` + `laravel/sanctum` `v4.3.3` also resolves cleanly (`110 installs, 0 conflicts`).
   - Rejected `architecture-gemini-argon.md`'s incompatible pairing of Laravel 12 with Filament v3.
2. **PostgreSQL 17 (`17.x` GA) Baseline & Client-Side UUIDv7 (`ADR-004`, `docs/architecture.md §2.1`):**
   - Retained **PostgreSQL 17 (`17.x` GA)** as the deliberate baseline because all UUIDv7 primary keys are generated in application code (`uuid` in Dart, `Ramsey\Uuid` in PHP)—eliminating any dependency on PostgreSQL 18's server-side `uuidv7()`—while `17.x` is universally available across Ubuntu 24.04 LTS packages and managed PostgreSQL providers with mature `btree_gist` and `pg_trgm` extensions. A Stage 2A (`Sprint 2.1`) PostgreSQL version & hosting compatibility gate verifies the target production database (never using a release candidate or beta build).
3. **Current Upstream SQLite Encryption (`sqlite3mc` Build Hook + Explicit `chacha20` Pre-Key Selection & Fail-Closed Verification, `P1-1`, `P1-8`):**
   - Verified upstream (`pub.dev` + `simolus3/sqlite3.dart` `UPGRADING_TO_V3.md` + `utelle/SQLite3MultipleCiphers`) that `sqlcipher_flutter_libs` is `0.7.0+eol` and that `SQLite3MultipleCiphers`'s documented default cipher is **`chacha20` (`sqleet` ChaCha20-Poly1305 AEAD)**—**not** AES-256.
   - Standardized on **`drift: ^2.35.0` + `sqlite3: ^3.8.0` with `hooks.user_defines.sqlite3.source: sqlite3mc`**, explicitly configuring **`PRAGMA cipher = 'chacha20'; PRAGMA legacy = 0;` BEFORE applying `PRAGMA key`**, verifying in **`debug`, `profile`, and `release` builds** that `SELECT sqlite3mc_config('cipher');` / `PRAGMA cipher;` equals `'chacha20'` (throwing a fatal `StateError` otherwise), and requiring a pre-feature Android + Windows proof-of-technology test at the start of Sprint 1.1.
   - Clarified OS key storage (`P1-8`, `G-P2-2`): Android uses `Android Keystore` (hardware TEE/StrongBox where confirmed by OS APIs, otherwise OS-isolated software keystore); Windows uses **Windows DPAPI (`CryptProtectData` via Credential Manager)**, which is **OS user-profile-scoped encryption** (not a hardware TEE).
4. **Provisional Separated Streaming Backup Encryption & Pre-Implementation PoT Gate (`DEC-06`, `G-P3-1`, `docs/architecture.md §10.2, §10.3`):**
   - `.walimbak` backups use a WAL-safe `VACUUM INTO` snapshot encrypted with an independent CSPRNG 256-bit `DEK` wrapped by a user passphrase (`Argon2id`) and/or printable 256-bit Recovery Key (`header_sha256` bound as `AAD`)—**never derived from the license key**.
   - Distinguished **Candidate A (`libsodium` `crypto_secretstream_xchacha20poly1305` via `sodium`/`sodium_libs`, preferred primary construction using `libsodium`'s native `24-byte` `secretstream_header`, `17-byte` `ABYTES`, per-chunk `ad`, and `CRYPTO_SECRETSTREAM_XCHACHA20POLY1305_TAG_FINAL = 0x03`—without manual per-chunk nonce derivation)** from **Candidate B (fixed-chunk RFC-8439/NIST STREAM construction over `64 KiB` chunks, fallback only if `libsodium` FFI fails the Sprint 1.4 PoT)**. Both candidates remain **provisional** until their integrity, nonce-uniqueness, staging-restore (`restore_staging.db.tmp`), and negative-test properties are demonstrated in the Sprint 1.4 PoT gate.
5. **Phase 1 Offline License Issuance (`ADR-012`, `P1-9`):** Added `tools/license-issuer` built around a clean `LicenseSigner` interface (`FileKeyLicenseSigner` / Hardware Token in Phase 1; `RemoteHsmLicenseSigner` / Filament in Phase 2).
6. **Unconditional `payments` Immutability Trigger + Immediate Server Revocation vs. Next-Online Local Cryptographic Erasure (`ADR-009`, `ADR-013`, `P1-2`):**
   - Database triggers (`BEFORE UPDATE OR DELETE ON payments`) reject **all** `UPDATE` and `DELETE` operations on every column of `payments`.
   - Each venue resides in its own encrypted SQLite database file (`venues/<venue_id>.db`) keyed by `key_venue_<venue_id>`. Revoking a device (`device_registrations.status = 'revoked'` -> `401 DEVICE_REVOKED`) or membership (`venue_memberships.is_active = false` -> `403 MEMBERSHIP_REVOKED`) takes effect **immediately on the server**, while local cryptographic erasure (deleting `key_venue_<venue_id>` and unlinking `venues/<venue_id>.db`, never executing `DELETE FROM payments`) executes on the device's **next successful online check**. Offline access on a disconnected device is bounded by the fail-closed 72-hour `OfflineAccessLease` (requiring online revalidation after any reboot and never promising immediate remote wiping of an offline device).

### 4.4 Sync Ordering, Binary Asset Sync, Auth-First Idempotency & Filtered Cursor (`P1-3`, `P1-4`, `G-P1-1`, `G-P1-2`)
- **Monotonic Local Outbox + Binary Asset Sync (`docs/architecture.md §6.1`, `G-P1-1`):** Replaced timestamp ordering with `outbox_seq INTEGER PRIMARY KEY AUTOINCREMENT`, parent-before-child dependency blocking (`depends_on_outbox_seq`), and pre-push S3/R2 binary upload (`PUT /api/v1/sync/assets/{sha256_checksum}`) for `generated_documents` PDFs and `venues` logos.
- **Auth-First Idempotency & Safe Masked Partial Updates (`P1-4`, `G-P1-2`):** `/api/v1/sync/push` enforces active authentication, active `device_registrations` (`status = 'active'`), and `venue_memberships` RBAC (`is_active = true`) *before* checking `sync_processed_operations`, verifies `payload_sha256` (`422 IDEMPOTENCY_PAYLOAD_MISMATCH`), and strips financial fields from reservation updates pushed by non-financial roles so operational edits (`guest_count`, `notes`) succeed safely.
- **Commit-Serialized `scanned_through_seq` Cursor (`P1-3`):** `/api/v1/sync/pull` scans contiguous 200-row windows of `sync_change_log` and returns `scanned_through_seq = MAX(seq)` of the scanned window so role-filtered clients advance cleanly past omitted financial pages without stalling or skipping unscanned bookings.

## 6. Impact of the Shared Android + Windows Flutter Requirement

### 6.1 Architectural Adjustments Incorporated
1. **Single Trilingual Flutter Application (`apps/owner`):**
   - Shares ~90% of code (`core/`, `database/`, `features/`, `l10n/` for `ar-DZ`, `fr-DZ`, `en`) across Android (`API 24+`) and Windows (`x64`).
   - Uses `AdaptiveShell` (`< 600dp` touch-first phone UI with bottom navigation and bottom sheets; `>= 600dp` / `>= 1024px` desktop `NavigationRail`, split views, and keyboard shortcuts).
2. **Five Resilient Platform Adapters (`lib/platform/`, `docs/architecture.md §4.4`):**
   - `DeviceIdentityProvider`: Persistent random Installation UUID stored in `SecureCredentialStore` + salted hash of `MachineGuid` (Windows) or `Settings.Secure.ANDROID_ID` (Android, with software-keystore fallback on low-cost devices).
   - `SecureCredentialStore`: Windows DPAPI Credential Manager (OS user-profile-scoped encryption) vs. Android Keystore (`EncryptedSharedPreferences`) storing per-venue `sqlite3mc` keys (`key_venue_<venue_id>`), auth tokens, signed `OfflineAccessLease`, `last_verified_elapsed_ms`, and `highest_observed_utc`.
   - `BackupStorageAdapter`: WAL-safe `VACUUM INTO` snapshot + `PRAGMA integrity_check` + provisional `64 KiB` streaming AEAD encryption (Candidate A `libsodium` `crypto_secretstream_xchacha20poly1305` preferred without manual per-chunk nonce derivation; Candidate B fixed-chunk RFC-8439/NIST STREAM fallback only if `libsodium` FFI fails the Sprint 1.4 PoT), executed deterministically in the foreground with staging restore (`restore_staging.db.tmp`) and a 7-day off-device export reminder banner.
   - `DocumentOutputAdapter`: Windows native print/save vs. Android Print Spooler and WhatsApp PDF share sheet.
   - `AppInstanceGuard`: Windows named mutex vs. Android single-task launch mode.
3. **Clear Single-Device Pilot vs. Multi-Device Commercial Boundary (`DEC-01`):**
   - **Stage 1A (`Sprints 1.1–1.3`)** builds the offline foundation and internal single-device Android pilot.
   - **Stage 2A (`Sprints 2.1–2.3`)** ships **`WalimApp Connect v1.0`**, linking individually authenticated users across Android phones and Windows PCs into a shared, synchronized venue calendar under configurable active-device tiers (`1` vs. `5` active devices).
   - **Stage 1B (`Sprint 1.4`)** ships **`WalimApp Local v1.0`** (desktop split-view polish, `.walimbak` streaming backups, and `.walimlic` offline licensing).
